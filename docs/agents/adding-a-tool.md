# Adding a new tool

Read this when you add or change an MCP tool. Code examples and patterns: [DEVELOPER.md](../../DEVELOPER.md).

1. **Use case first.** Put the logic in `internal/app/{domain}/` (typed input, repo-owned result). `internal/app/**` must not import mcp-go or the Forgejo SDK (depguard in `.golangci.yml`); reach Forgejo through the port in `internal/forge/`, bridged by `internal/forge/<domain>adapter/`.
2. **MCP adapter.** In `internal/operation/{domain}/`: a `mcp.NewTool()` definition, an argument struct (`json:"name"`, `required:"true"`) decoded with `decode.Lax`, then a call to the use case. Pass one hint annotation as the second `mcp.NewTool` argument: `annotate.Read()` for get/list/search/check/download, `annotate.Write()` for create/update/other writes, `annotate.Destructive()` for delete/remove/cancel (`internal/operation/annotate`). Add the tool's name and class to `expectedHints` in `internal/operation/annotations_test.go`; that test fails for a tool with no class. Numbers are `float64` in the argument struct and are read through `internal/numarg` (see DEVELOPER.md, Numeric arguments), except where a tool's error text depends on how the number was given: those type it `any` and pass it to the same module. **Lean marker:** give an argument `lean.Keep("clause")` in its option list, next to its `mcp.Description`, when its name and type do not show how to fill it in: a format (comma-separated list, RFC3339 time), an allowed-value list (`state`, `sort`, `type`), or a rule (mutually exclusive, empty clears it). The clause is one short phrase, at most 120 bytes, and is what `--lean` serves in place of the description. Never mark `owner`, `repo`, `index`, `page`, `limit` or `verbose`. `internal/operation/lean_test.go` fails for a marked argument with no description, a clause that is empty or too long, or a never-marked name marked.
3. **Register** in the domain's `RegisterTool(s *server.MCPServer, f forge.Factory)`. Then add the tool's name to its toolset in `internal/toolset/toolset.go`; the registry test fails for a tool in no toolset.
4. **New domain:** import and call it in `internal/operation/operation.go`.
5. **Pin it with tests.** `mcptest.SchemaSnapshot` and `mcptest.Golden` per tool, `mcptest.ArgsMatchSchema` per argument struct (`go test ./internal/operation/{domain} -update` writes the files), and use-case tests in `internal/app/{domain}/`.
6. **Go through the port.** The adapter's `run` helper calls `f.For(ctx)` per request and hands the port to the bridge. A new endpoint is a port method, its adapter in `internal/forge/sdk/`, its fake and a contract case. Nothing outside `internal/forge/sdk` builds an SDK client or an HTTP request to Forgejo.
   **Escape API paths** in the adapter's raw-HTTP methods (`a.rawJSON`, `a.rawDo`, `a.raw.doAPIRaw`, `a.raw.doMultipart`): build the path with `forge.APIPath("repos", owner, repo, …)`, which escapes every segment. A hand-rolled `fmt.Sprintf("/repos/%s/…")` lets an owner containing `/` or `?` retarget the request at another endpoint; `scripts/ci/check-api-path-escaping.sh` fails the build on it. Append query strings to the `APIPath` result.
7. **Bound the output.** If response size depends on data (not tool semantics), the tool MUST satisfy [output-bounding.md](../design/output-bounding.md): client-controlled bound, resumability and documented parameters. A list use case gets its bound from the list module (`internal/app/list`): `list.Run` for a paged list, `list.Window` for a port that reports its own `has_next`, `list.Cut` for a list Forgejo does not page. It does no page/limit parsing or ceiling check of its own. Read raw page/limit arguments with `decode.PagingArgs`. Put the checklist from that doc under the PR body's Evidence section (the `/pr` template has no separate slot).
8. **README row.** Every registered tool needs a row in the README "Available Tools" table, and every `forgejo://` resource template a row in the "Resources" table. `scripts/ci/check-readme-tool-coverage.sh` fails the build on a tool or template with no row: it compares the `…ToolName` constants and registered URI templates under `internal/operation/` against the tables.
